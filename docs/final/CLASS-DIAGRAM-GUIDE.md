# Complete class diagram guide

Source: `4aef4b56657c13fee5f19befe995195a378abe3a`. Includes all 76 top-level production Java types across application, common and six module packages.
Test classes are listed in TEST-REPORT.md; they are not production entities.

## What to print or share
Use Complete_Class_Diagrams.pdf for the overview, logical data associations and module pages.
The PDF atlas boxes list stored fields and declared business method names; getters/setters are omitted from the pictures to keep them readable.
Only neighbouring dependency arrows are drawn in the atlas to avoid crossing class text; every dependency appears in the full editable Mermaid UML.
Full signatures, constructors, accessor methods and nested helper notes are in CLASS-INVENTORY.md.
The complete Mermaid source includes all extracted fields and method signatures and can be edited.
SVG module pages are vector exports and can be zoomed or printed in A2; printing a dense module page on A4 reduces legibility.

## Notation
Solid arrow: a direct field dependency, usually provided by constructor injection.
Dashed line with a hollow triangle in Mermaid: interface realization (implementation).
Dashed arrow: method input/output dependency. Enum and record labels describe their Java declaration.
Database associations are shown separately and labeled as ID-based foreign keys, not invented JPA object collections.
MovingCompanyService and MovingCompanyDAO are concrete classes. UserRepository implementation is generated by Spring Data.

## How to explain it
Start at a controller. Follow its service dependency, then repository/DAO, then the stored record.
Point out request/response DTOs and show where session identity and validation are used.
Use the association page to explain how user IDs and property IDs connect modules without object inheritance.
